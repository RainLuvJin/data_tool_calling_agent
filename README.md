# Data Tool Calling Agent

一个基于大语言模型（LLM）的数据分析 Agent 项目，通过自然语言理解用户需求，自主选择工具并执行操作。

项目以招聘岗位 CSV 数据集为基础，从手写 Function Tools 开始，逐步实现 LLM Tool Calling、MCP 工具接入与 Skills 扩展，理解 Agent 从需求理解到工具执行的完整过程。

## 1. 项目目标

本项目旨在学习和实践以下能力：

- **LLM Tool Calling**：让模型根据用户需求自主选择工具，而不是由 Python 写死调用流程。
- **Function Tools**：手动设计工具函数、参数与返回结果。
- **数据处理**：使用 Pandas 读取、筛选和分析招聘数据。
- **MCP**：通过 MCP SDK 接入标准化的外部工具。
- **Skills**：按照约定的规范组织可复用的任务指令与操作流程。
- **工程实践**：逐步完善模块划分、异常处理、日志记录和自动化测试。

## 3. 核心架构

```text
用户自然语言请求
        |
        v
   DeepSeek LLM
        |
        | 分析需求，选择工具并生成参数
        v
   Tool Calling Agent
        |
        v
   参数校验与工具分发
        |
        +--------------------+
        |         |          |
        v         v          v
   数据读取工具  岗位筛选工具  薪资统计工具
        |         |          |
        +---------+----------+
                  |
                  v
          Python / Pandas
                  |
                  v
             CSV 数据集
                  |
                  v
          工具执行结果返回 LLM
                  |
                  v
             自然语言回答
```

LLM 负责理解用户意图、选择工具并生成参数；Python 负责参数校验、执行工具和处理数据。工具执行结果可以再次交给 LLM，由模型组织成易读的回答。

## 4. 核心工具设计

### Tool 1：数据读取与查看

**目标：** 根据用户的要求查看数据集内容。

示例请求：

- “看看数据集前 20 行。”
- “有哪些字段？”
- “随机抽取 10 条岗位记录。”

预期能力：

- 读取 CSV 文件。
- 查看前 N 行或指定数量的记录。
- 查看字段名称与数据概况。
- 限制返回行数，避免一次性输出过多数据。

实现思路：

将读取能力封装为 Python 函数，例如 `inspect_dataset()`。LLM 根据用户请求选择该工具，并传入行数等参数。

例如，用户要求查看前 20 行时，工具内部可以调用 Pandas 的 `DataFrame.head(20)`。

> 安全原则：模型不需要临时生成并执行任意 Python 代码。应优先调用预先定义、经过校验的工具函数。

### Tool 2：岗位筛选

**目标：** 根据用户指定的条件筛选招聘岗位。

示例请求：

- “找出要求 Python 技能的岗位。”
- “筛选北京的全职岗位。”
- “找出薪资下限至少为 20,000 美元的岗位。”
- “找出同时满足地点和技能要求的岗位。”

预期能力：

- 按地点筛选。
- 按技能关键词筛选。
- 按工作类型筛选。
- 按最低年薪筛选。
- 支持多个条件组合。

实现思路：

将自然语言转换为结构化参数，再由 Pandas 执行条件筛选。

例如：

```json
{
  "skill": "Python",
  "employment_type": "Full-time",
  "min_salary_usd": 20000
}
```

具体字段与筛选规则以数据集实际内容为准。当前阶段以关键词匹配和结构化条件为主，后续可扩展语义检索。

### Tool 3：薪资统计

**目标：** 分析招聘数据中的年薪信息，帮助用户了解岗位薪资分布。

示例请求：

- “统计数据集中有多少岗位披露了年薪。”
- “计算年薪中位数和平均数。”
- “统计年薪最高值与最低值。”
- “比较不同工作类型的薪资分布。”

预期能力：

- 统计有效薪资记录数量。
- 计算平均年薪与年薪中位数。
- 计算最低值与最高值。
- 按工作类型或其他字段进行分组统计。

实现思路：

使用 Pandas 对年薪字段进行数值转换，处理缺失值后进行统计。

当前数据集包含 `salary_annual_min_usd` 和 `salary_annual_max_usd` 等字段。统计时需要明确使用薪资下限、上限还是区间中点，避免将不同口径混为一谈。

## 5. 数据集

项目使用招聘岗位数据集：

- 数据来源：[Job Market Intel Corpus — Hugging Face](https://huggingface.co/datasets/Shifat2110724169/job-market-intel-corpus)
- 数据格式：CSV
- 主要内容：岗位名称、地点、工作类型、职位描述、技能要求、年薪等信息。

部分关键字段：

| 字段                      | 含义       |
| ----------------------- | -------- |
| `title_en`              | 英文岗位名称   |
| `location_raw`          | 原始地点信息   |
| `employment_type`       | 工作类型     |
| `description_en`        | 英文岗位描述   |
| `required_skills_text`  | 必需技能文本   |
| `salary_annual_min_usd` | 年薪下限（美元） |
| `salary_annual_max_usd` | 年薪上限（美元） |

实际使用前需要检查 CSV 的字段名、空值比例、薪资单位与数据质量。

## 6. 开发路线

### Phase 1：手写 Function Tools

- [ ] 完成数据读取工具。
- [ ] 完成岗位筛选工具。
- [ ] 完成薪资统计工具。
- [ ] 为工具添加参数校验和异常处理。
- [ ] 使用普通 Python 调用逐个验证工具结果。

### Phase 2：接入 DeepSeek Tool Calling

- [ ] 为每个工具定义名称、描述与 JSON 参数 Schema。
- [ ] 将工具定义发送给 LLM。
- [ ] 解析模型返回的工具调用请求。
- [ ] 由 Python 根据工具名称分发调用。
- [ ] 将执行结果返回给 LLM。
- [ ] 支持多轮工具调用，直到模型生成最终回答。

### Phase 3：接入 MCP

- [ ] 使用 MCP SDK 编写或接入一个工具服务。
- [ ] 学习工具发现、参数 Schema 与调用结果。
- [ ] 让 Agent 通过 MCP 客户端调用外部工具。

### Phase 4：实现 Skills

- [ ] 按照选定的 Skills 规范组织任务指令与操作流程。
- [ ] 为岗位分析等复杂任务设计可复用的 Skill。
- [ ] 明确 Skill 与 Tool 的职责边界。
- [ ] 观察 Skill 如何指导 Agent 组合多个工具完成任务。

## 7. 设计原则

1. **先理解，再自动化**：先手动调用工具，确认函数行为正确，再接入 LLM。
2. **模型决策，程序执行**：LLM 提出工具调用请求，程序负责校验并执行。
3. **工具职责单一**：读取、筛选、统计分开实现，便于测试和复用。
4. **结果可验证**：数据统计和筛选结果应能追溯到原始数据。
5. **安全可控**：限制工具权限、参数范围、返回数据量，避免执行任意代码。
6. **渐进式扩展**：先实现可运行的最小版本，再增加 MCP、Skills 与复杂工作流。
